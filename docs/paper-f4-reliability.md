# F4 数据分析的执行与恢复

F4 由模型规划方法和变量，宿主负责读取数据、运行计算、收集结果、保存恢复点及常用图形。常见计算可直接使用注册工具；特殊方法和任务逻辑由模型生成 Python，在同一个流程中执行。统计方法不再受注册工具清单限制。

修改仅涉及 F4 及其科学计算依赖。F3 输入、F4 对外交付格式、F5 消费端及下游交接测试不变。没有旧执行模式开关或旧统计代码协议的兼容路径。

## 任务与方法

- 模型规划使用 `CompactPlan.tasks`，按 summary、comparison、correlation、regression、probability、code 区分字段。后台将紧凑任务编译成内部执行 `Plan.jobs`；内部 Job 不再作为模型规划输入协议。没有旧模型响应格式的回退分支。
- 分组汇总使用 `group_by` 和 `metrics`。例如十种方法、五个数据集、两个指标只需一个任务，后台从完整数据发现实际组合并展开一百个计算项，保留全部结果。不会从分类值做笛卡尔积，不会仅使用预览行，也不会为了数量上限截断。最多一百个紧凑任务、一千个展开项。
- 比较任务对选中组和基线同时应用分层条件，基线独有的分组也会保留并显式报缺少比较数据。每个指标独立执行缺失处理；相关矩阵只展开无序变量对；回归可声明多个系数；分组拟合使用各组独立模型实例。初始计划仅声明图表意图和对应任务；计算完成后，后台展开实际结果 ID，再单独规划图表。
- 注册工具继续提供均值、计数、独立/配对差、Welch/配对 t、OLS 系数、解析 Beta 后验及 Pearson/Spearman。工具在其明确的适用条件下使用，不强制替代其他方法。
- 其他方法或特殊处理通过任务的 `procedure` 声明计算过程，`outputs` 声明结果键和含义；`columns` 声明额外输入变量。已知方法需要不同实现时也可填写这些字段。一个任务可以返回多个分组、系数或区间。
- 代码仅实现 `analyze(frames, params, rng)`。`frames['analysis']` 是选中数据；有基线时另提供 `frames['baseline']` 和两组并集 `frames['combined']`，均保留原始行索引。`params` 是只读映射，必须通过键访问；直接赋值立即失败，嵌套参数修改也会被检测。宿主还提供固定种子的随机生成器及 `emit`/`diagnose`。函数签名、数据说明和模型骨架共用 worker 中的 `INTERFACE`；提示包含实际禁止名称/属性和可用库。没有旧函数签名兼容。
- 运行时明确告知实际可用的 NumPy、SciPy、pandas、statsmodels、scikit-learn 及版本；新增 statsmodels 依赖。模型优先调用库函数，必要时实现任务逻辑。缺少专门依赖、数据或有效研究设计时仍可能无法完成，不能冒充已经支持任意统计方法。
- 筛选和完整观测处理由宿主执行。代码不必自己解释两组来源索引；宿主直接构造明确命名的 DataFrame。自定义缺失处理需明确声明，不能擅自改变比较范围。当前支持原始表或已有的一对一/多对一关联视图，代码任务也可用 `inputs={名称: {table_id, columns, filters, missing_policy}}` 声明附加 DataFrame。多来源结果通过 `emit(rows={输入名称: 原始行索引}, n=有效样本量)` 保留各原表来源；复杂转换由代码执行，不由后台猜关联规则。
- 结果仍交付现有 `Finding`。代码任务使用 `task_id:output_id` 标识多个结果；每项保留数值、单位、样本量、区间/检验及来源。纯检验可无点估计。成对、聚类或汇总试验的有效样本量由代码明确返回，不把原始行数直接当独立样本量；无法按同一单位确定的排除数为 null。

例如：中位数与分位数可作为一个任务的两个输出；Logistic 回归可输出截距和多个系数；Bootstrap 可生成明确类型和水平的区间。无需为这些方法逐个新增执行器或修改下游合同。

## 校验边界

| 类型 | 处理方式 |
| --- | --- |
| 数据类型、字段数、真实来源、筛选字段、设计依据引用 | 保留阻断校验，不补造数据 |
| 注册工具的单位、配对键、统计前提 | 保留其方法专属检查，避免套用到所有自定义方法 |
| 自定义输出键、来源行范围、样本量边界、有限数值、区间顺序、p 值/概率语义 | 保留阻断校验；遗漏输出或修改锁定任务进入局部修复；必要诊断未通过返回分析决策，普通诊断失败作为限制披露 |
| 代码隔离、超时、导出格式、SVG 主动内容 | 保留执行和交付检查 |
| 常规图表的结果引用、维度冲突、单位混合、已绑定数值与区间 | 保留图表阶段校验，失败不要求统计重算 |
| 重复的同一来源列引用 | 在副本中去重 |
| 标签误用任务 ID 或限定列名 | 仅在对应唯一且标签不冲突时规范化，否则局部修复 |
| 图题/标签语言、完整但较长的行标签 | 不作为统计正确性的阻断条件，交由呈现处理 |
| 解释正文中的年份、编号、数值或模型名称 | 不按数字字符拦截，不维护数字白名单；保留目标覆盖和结果引用检查，提示模型依据已有结果与输入事实撰写 |

自定义代码通过执行、数值结构及来源检查，不等于另一统计实现独立复算，也不证明方法选择、独立性假设或科学解释正确。诊断明确写出这一边界，不报告不存在的独立验证。

## 图表与修复

已准备好面板的常规图优先调用固定绘图组件。模型可用 `render_mode=code` 自行编排，特殊图型可选 `custom` 及其基础风格；这两种方式均保留现有绘图校验。自定义分析结果直接进入绘图数据和结论证据，不强行解释成均值或相关系数。图表意图中的 `task_ids/output_keys` 在计算完成后展开为真实结果引用。每张图仅检查自身新增映射、引用和文件，不再校验整份统计计划。

统计计划、各代码任务、结论和各图表有独立的尝试预算。`LAZYMIND_PAPER_ANALYSIS_ATTEMPTS`（1..3，默认 3）控制计划的局部修复次数和结论的尝试上限；代码最多使用当前模型生成一次、局部修复一次；`LAZYMIND_PAPER_ANALYSIS_TIMEOUT`（默认 180 秒，1..3600）约束每次代码执行。代码任务最多同时执行两个。`LAZYMIND_PAPER_PLOT_ATTEMPTS`（1..5，默认 3）控制每张图的计划修复次数与绘图尝试上限。

计划修复使用 `PlanPatch`，图型修复使用 `FigurePatch`，提示中 schema 与实际格式一致。下一次代码修复携带上次代码及具体错误，只修改该任务；图表修复不改统计任务及选定结果。成功的兄弟任务不会因另一个任务失败而丢弃。无法完成时明确报告未完成，不删减要求或发布缺项的 F4 结果。

## 恢复点

工作流绑定恢复目录。生产目录为 `<root>/<user>/<task>` 时，恢复点位于 `<root>/<user>/.paper-f4-recovery/<conversation hash>/<request hash>/`；同一会话的新任务可复用同一请求。直接调用算法且未绑定工作区时不持久化。

先保存已验证的计划和注册计算结果，再按代码任务、结论、图表分别保存成功结果。请求标识包含规范化输入、请求文字、依赖版本、相关代码和绘图资源摘要。输入或实现变化使恢复点失效；损坏文件重新计算。恢复结果重新经过相应结构、引用或导出检查。

注册组件现在也逐计算项保存成功结果，失败时保存待修复计划及具体问题。同次局部修复或同会话后续重试，只重新计算失败或内容发生变化的项；未完成的一批任务不再导致成功项重算。计算项标识包含自身范围和实际使用的模型，输入与实现仍由请求级指纹隔离。`compact-plan.json` 和 `plan-expansion.json` 分别记录模型原始紧凑计划及展开对应关系，公开进度分别显示分析任务数和计算项数。

文件采用原子替换、内容摘要和单文件 32 MiB 上限。写入失败不影响当前执行，但下次不能保证复用。恢复文件包含数据分析结果和图表，应按用户任务数据管理；没有外部缓存服务、跨主机恢复或自动过期机制。

## 验证范围

离线测试覆盖 F4 发布、真实 SVG/PNG/PDF 渲染、固定组件和自定义布局、不同输入的多结果分析、statsmodels Logistic 回归、SciPy 非参数检验和 Bootstrap、无效结果拦截、局部反馈、失败后的任务/图表复用以及恢复点隔离和失效。

模型返回由测试替身提供，计算、沙箱和渲染使用真实实现。这些测试用于确认通用接口及恢复机制工作，不是某个弱模型的成功率评估，也不保证任意研究任务成功。此前版本已有部署；本次紧凑计划及接口调整仅在隔离工作树修改、临时容器测试，没有更新该部署或重启服务。

## 新计划协议与需求覆盖

模型必须返回 `tasks + requirements + figure_requests`；旧 `jobs` 或初始完整 `figures` 响应不被兼容。内部执行任务使用明确的 `execution=component|code`，不再根据 procedure 是否为空猜路径。恢复点协议为 v2，旧恢复点直接失效。

数据概况来自全部数据。模型可在最多三轮、每轮最多四项的只读查询中，按实际字段、筛选和分页查看 rows、levels、cells、profile 或 relation；查询结果最多 32 KiB，超限返回具体错误，不静默截断。附加输入使用同样的真实列名和显式缺失策略。

原请求片段有宿主生成的稳定 ID。`requirements` 逐项绑定任务、必需字段（value/interval/test/probability）、图表或呈现要求；被用户要求引用的任务自动视为必需。复杂请求（超过四个片段或八百字符）额外核对一次语义遗漏，其余不增加全面模型审查。结构对应不能证明模型完整理解了自然语言；验收仍需要独立案例和数值参照。

可选任务必须在执行前声明；局部修复不能把必需任务改为可选、删除必需输出或更换用户锁定的方法参数。可选失败记入限制，不阻断已满足的必需交付。`requirement-delivery.json` 保存需求到实际结果/图表的对应。

代码执行的 AST 提前诊断独立于绘图规则，实际隔离仍由容器、Landlock 和 seccomp 完成。必要诊断由 `required_diagnostics` 声明，或计算代码明确标记 blocking；一般失败诊断只披露限制。数值诊断失败最多返回一次分析决策局部修复。失败代码和具体错误也保存为恢复点；成功任务的缓存只绑定自身使用的模型参数，不因无关模型变化失效。

没有备用模型切换、备用角色环境变量或自动升级模型。当前模型修复仍失败时，只有事前明确声明 `equivalent_component`、同一标准方法、同一数据范围、完整参数、单结果且无自定义转换/额外输入/必要代码诊断的任务能调用等价组件。其他任务如实报告未完成，不能通过替换估计方法、区间算法或删减结果来成功。

## 真实模型验收入口

`tests/fixtures/paper_f4/live_cases.json` 固定二十类有效任务，每类三次；`run_paper_f4_live.py` 使用真实模型、真实沙箱及独立 NumPy/SciPy/statsmodels 数值参照，每次独立进程与恢复目录。保留清单与实现摘要、全部运行记录和失败；错误输入另行统计，不算分析成功。Bootstrap 的蒙特卡洛区间使用明确容差，其他数值严格匹配。

首次独立模型连接预检返回 HTTP 401（authentication_failed），在进入分析前失败。随后确认验收误用了部署环境变量中的密钥，该密钥与网页当前用户模型配置中的密钥不同；模型名与接口地址相同。这不是网页模型配置失败的证据。验收脚本现要求提供后端解析的完整 llm 配置（含实际 base_url），不再硬编码模型或从供应商环境变量猜密钥。真实模型验收状态以独立验收目录记录为准，不能从离线测试推断弱模型成功率。失败记录保存在独立验收目录的 `smoke-v1/01_mean-1/result.json`，运行日志及私有模型配置不提交仓库。本轮没有部署或重启现有服务。
